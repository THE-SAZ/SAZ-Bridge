Introduction

🎯What is SAZ Bridge?

SAZ Bridge is a modern, lightweight, and entirely free subscription management panel for V2Ray / Xray / Vmess / Vless providers, built on Cloudflare Workers.

If you're running proxy servers and need to distribute configuration links to users, SAZ Bridge gives you a complete, professional-grade management platform without a single line of backend code and without any VPS or hosting fees.

It runs entirely on Cloudflare's global edge network — 300+ locations worldwide — giving your users millisecond latency no matter where they are. Configuration, storage, and management all happen inside a Cloudflare Worker and its Key-Value store.

⚡
Zero Configuration
No secrets, no environment variables. Everything lives in KV and is set up via the built-in wizard.
🌍
Global Network
Runs on Cloudflare's edge — fastest response for every user around the world.
💰
Completely Free
The Cloudflare free tier is more than enough for thousands of users per day.
🎨
Windows XP Theme
Nostalgic Luna theme for the admin panel, with modern UX improvements.
💡
A Bridge Between Old & New SAZ Bridge takes the robust, well-tested approach of classic proxy panel software and modernizes it for the serverless era.

🔑 Data Model

All data is stored in a single KV namespace (SUB_KV) under these keys:

Key Value Type Purpose
configJSONGlobal settings: password hash, sub path, theme, language, bot token
usersJSON ArrayAll user records with tokens, quota, expiry, links
groupsJSON ArrayColor-coded groups for organizing users and subs
sub_linksJSON ArrayCustom subscription links with sources, prefix, visits
session:*StringActive admin sessions (TTL: 24h)
Installation

🚀Deploy in 5 minutes

Choose your preferred method — Dashboard for simplicity, Wrangler CLI for power users.

Open Cloudflare Dashboard
Navigate to dash.cloudflare.com and sign in (or create a free account).
Create a Worker
Go to Workers & Pages → Create → Worker. Name it saz-bridge and click Deploy.
Paste the Code
Click Edit code, delete the default content, and paste the full _worker.js from the repository. Save & Deploy.
Create a KV Namespace
Go to Workers & Pages → KV → Create namespace. Name it SUB_KV.
Bind KV to Worker
In your worker → Settings → Variables → KV Namespace Bindings:
Variable name: SUB_KV · KV namespace: SUB_KV
Visit your Worker URL
Open https://saz-bridge.YOUR-SUBDOMAIN.workers.dev. The Setup Wizard appears!
✨
Zero secrets required You don't need to add any environment variables. Every setting is configured inside the panel and stored in KV.
Install prerequisites
Node.js 18+ and npm are required.
# Install Wrangler globally
npm install -g wrangler

# Login to Cloudflare
wrangler login
Clone the repository
git clone https://github.com/THE-SAZ/saz-bridge.git
cd saz-bridge
npm install
Create KV namespaces
# Production namespace
wrangler kv:namespace create "SUB_KV"
# → Copy the "id" to wrangler.toml

# Preview namespace
wrangler kv:namespace create "SUB_KV" --preview
# → Copy the "preview_id" to wrangler.toml
Edit wrangler.toml
name = "saz-bridge"
main = "_worker.js"
compatibility_date = "2024-11-01"

[[kv_namespaces]]
binding = "SUB_KV"
id = "PASTE_YOUR_KV_ID_HERE"
preview_id = "PASTE_YOUR_PREVIEW_ID_HERE"
Deploy
wrangler deploy

# Or for local development:
wrangler dev

For automated deployments on every push, use GitHub Actions. Create .github/workflows/deploy.yml:

name: Deploy SAZ Bridge

on:
  push:
    branches: [main]
  workflow_dispatch:

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Setup Node
        uses: actions/setup-node@v4
        with:
          node-version: 20

      - name: Install dependencies
        run: npm ci

      - name: Deploy to Cloudflare
        uses: cloudflare/wrangler-action@v3
        with:
          apiToken: ${{ secrets.CF_API_TOKEN }}
          secrets: |
            ADMIN_PASSWORD
        env:
          ADMIN_PASSWORD: ${{ secrets.ADMIN_PASSWORD }}
🔑
Required Secrets Add CF_API_TOKEN in your repository secrets. Get it from Cloudflare Dashboard → My Profile → API Tokens with "Edit Cloudflare Workers" template.

Configuration

⚙️Panel Settings

All settings are managed from the Settings tab inside the admin panel.

Setting Default Description
defaultLang fa The default panel language. One of: fa, en, ru, zh.
subPath sub URL segment used for subscription feeds. Keep it random for security (e.g. x7k9m2).
theme luna Visual theme. One of: luna, classic, silver.
announcement empty A short message shown on the dashboard home. Max 500 characters.
botToken empty Telegram bot token from @BotFather. Enables webhook and inline button features.
passwordHash — SHA-256 hash of the admin password. Set during Setup Wizard or via Settings.
⚠️
Choosing a Secure Sub Path Avoid guessable paths like sub or link in production. Use a random string such as br-7k3p9x.

Subscriptions

🔗Subscription Manager

Build custom subscriptions that aggregate multiple users' links under one URL.

🎯 What is a subscription?

A subscription is a single URL that returns a Base64-encoded list of proxy links. Clients like V2RayNG read this URL and automatically add all the configs inside.

📐 URL format

https://YOUR-WORKER.workers.dev/{SUB_PATH}/{TOKEN}

🧩 Two kinds of subscriptions

👤
User Subscription
Automatically created for every user. Uses their individual token. Consists only of their own links.
🔗
Custom Subscription
Built from the Sub Manager. Combines multiple users' links + direct links. Has its own token and visit counter.

🎛️ Custom subscription options

Option Description
name Internal name for identification.
prefix Icon/emoji prefix shown in clients (e.g. 🌉 SAZ).
group Assign to a group for organization.
sources Array of user tokens to pull links from.
directLinks Additional links not tied to any user.
quotaGB Total traffic limit for the subscription (0 = unlimited).
days Days until subscription expires.

📤 Response format

The subscription endpoint returns the links joined by newlines, encoded as Base64:

vmess://eyJ2IjoiMiIsInBzIjoi...
vless://uuid@host:443?type=ws...
trojan://password@host:443...
ss://base64@host:8388...

Response headers include standard subscription metadata:

Content-Type: text/plain; charset=utf-8
Cache-Control: no-store, no-cache
Profile-Update-Interval: 6
Subscription-Userinfo: upload=0; download=12345; total=53687091200; expire=1735689600

Telegram Bot

🤖Telegram Integration

Let your users retrieve their subscription link directly from Telegram — no login needed.

🔧 Setup

Talk to @BotFather
Open Telegram, search for @BotFather, and send /newbot. Follow the instructions to get your bot token.
Paste token in the panel
In SAZ Bridge → Bot tab → paste the token and click Connect Bot. The webhook is set automatically.
Link users to Telegram
Get each user's Chat ID from @userinfobot and enter it in their user record.
Done!
Users can now send /start to the bot and get their subscription, usage stats, and more.

💬 Available commands

Command Description
/startShow welcome message with inline keyboard.
/mysubReturn the user's personal subscription URL.
/usageDisplay traffic usage with a progress bar.
/helpShow all available commands.
📢
Broadcast From the Bot tab, you can send a message to all linked users at once — useful for announcements.
Backup & Restore

💾Never lose your data

Export everything as JSON, migrate between workers, or restore from a previous snapshot.

📤 Exporting

Navigate to Backup → Export JSON. A file named saz-bridge-backup-YYYY-MM-DD.json is downloaded containing:

  • ⚙️ All configuration (excluding password hash)
  • 👥 Every user record
  • 📁 All groups
  • 🔗 Custom subscriptions
{
  "version": "0.0.7",
  "app": "SAZ Bridge",
  "exportedAt": "2024-12-01T12:00:00Z",
  "config": {
    "subPath": "sub",
    "defaultLang": "fa",
    "theme": "luna",
    "announcement": ""
  },
  "users": [ ... ],
  "groups": [ ... ],
  "subLinks": [ ... ]
}

📥 Importing

Use Backup → Restore and select a previously-exported JSON file. Your current data will be overwritten — make a fresh backup first!

⚠️
Import overwrites everything Import replaces users, groups, and subscriptions entirely. The admin password is preserved.

API

📡API Reference

Programmatically manage everything through JSON endpoints.

🔑
Authentication All endpoints require a valid session cookie. Obtain it by POSTing to /login with the admin password.

🔐 Authentication

POST /login

Authenticates with the admin password. Sets a session cookie on success.

curl -X POST https://your-worker.workers.dev/login \
  -d "password=YOUR_PASSWORD" \
  -c cookies.txt
GET /logout

Destroys the session and redirects to login.

👥 Users

POST /api/user

Create a new user. Returns the generated token.

{
  "name": "Ali",
  "quotaGB": 50,
  "days": 30,
  "group": "grp_abc123",
  "tgId": "123456789",
  "links": "vmess://...\nvless://..."
}
PUT /api/user/:token

Update an existing user. All fields are optional.

DELETE /api/user/:token

Delete a user permanently.

🔗 Subscriptions

POST /api/sub

Create a custom subscription.

{
  "name": "Netflix Sub",
  "prefix": "🌉 SAZ",
  "group": "grp_abc123",
  "sources": ["user_token_1", "user_token_2"],
  "directLinks": "vmess://...",
  "quotaGB": 100,
  "days": 60
}
PUT /api/sub/:id

Update a subscription.

DELETE /api/sub/:id

Delete a subscription.

📁 Groups

POST /api/group 
{ "name": "VIP", "color": "#7FBA00" }
DELETE /api/group/:id

Delete a group and detach its members.

⚙️ Configuration

GET /api/config

Get current configuration (password hash and bot token removed).

POST /api/config

Update configuration.

🤖 Bot

POST /api/bot/set-webhook

Register the Telegram webhook.

POST /api/bot/unset-webhook

Remove the webhook.

POST /api/bot/broadcast

Send a message to all linked users.

{ "text": "Service maintenance at 03:00 UTC" }

💾 Backup

GET /api/backup

Download full backup as JSON.

POST /api/restore

Restore from a backup JSON. Overwrites existing data.

📡 Subscription Feed

GET /{subPath}/:token

Returns Base64-encoded subscription. Content-Type varies by User-Agent (text/yaml for Clash, text/plain otherwise).

🔔 Telegram Webhook

POST /tg-webhook

Called by Telegram for incoming updates. Not intended for direct use.

Security

🔐Built-in Security

SAZ Bridge follows modern security best practices out of the box.

🔒
SHA-256 Password Hashing
Passwords are never stored in plain text. Only a salted SHA-256 hash lives in KV.
⏱️
24-Hour Sessions
Sessions automatically expire after 24 hours. No permanent cookies.
🍪
Hardened Cookies
HttpOnly + Secure + SameSite=Lax — the browser can't read them from JavaScript.
🔒
HTTPS Enforced
Cloudflare provides automatic HTTPS with HTTP/3 and TLS 1.3.
🧼
Input Sanitization
All user input is validated and escaped to prevent XSS and injection attacks.
🛡️
Rate Limiting Ready
Enable Cloudflare's rate limiting rules to prevent brute-force attacks.

💡 Recommended practices

  • Use a strong password (12+ chars, mix of cases, digits, symbols).
  • Randomize subPath (avoid sub or link).
  • Enable Cloudflare Access for /admin if possible.
  • Rotate the admin password every few months.
  • Take regular JSON backups.

Troubleshooting

🔧Common Issues

Solutions to problems users frequently encounter.

Cause: JavaScript error or missing KV binding.
Fix: Open DevTools (F12) → Console. Check that the SUB_KV binding is configured. Try a hard refresh (Ctrl+Shift+R).
Cause: No valid proxy links in the user's configuration.
Fix: Edit the user and paste at least one valid link starting with vmess://, vless://, trojan://, or ss://.
Cause: Webhook not set, or token invalid.
Fix: Panel → Bot tab → paste token → click Connect Bot. Test with /start in Telegram.
Cause: Free tier provides only 1,000 KV writes/day.
Fix: Subscriptions update traffic on each request. Reduce update frequency on client, or upgrade to Workers Paid plan.
Fix: Delete the config key from KV via Cloudflare Dashboard. Reload the page — the Setup Wizard appears and you can set a new password.
Cause: Client can't parse some links.
Fix: Verify the links are correctly formatted. Test the URL in a browser — it should return plain Base64 text.
